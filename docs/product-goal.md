# Brevity Product Goal

Brevity exists to become the fastest and most pleasant place to review, approve, and merge AI-generated software work.

The primary product is not orchestration infrastructure.

The primary product is operator leverage.

A user should be able to:

* dispatch work
* observe progress
* inspect changes
* review results
* approve or reject work
* prepare merges

without leaving Brevity.

## Priorities

1. Review workflow
2. Diff visibility
3. Worktree inspection
4. Merge preparation
5. Operator awareness
6. Keyboard-first workflows
7. Professional UX/UI

## Deprioritized

Unless directly improving operator workflows:

* queue contracts
* scheduler contracts
* execution contracts
* daemon architecture
* distributed runtime
* additional read-only reports

## Litmus Test

Before implementing a feature, answer:

"Will this make a developer more likely to open Brevity instead of Codex directly?"

If not, reconsider the priority.
